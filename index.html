Safety

18650 batteries store a lot of energy. Insert them the right way round (check + and −), never short the terminals, switch the robot off when you are not using it, and only charge them in a proper 18650 charger with someone watching.

Module 1

Set up your PC

You need three things before you can upload code: the Arduino IDE, the ESP32 board package, and the CH340 USB driver. Do this once per computer.

STEP A

Install Arduino IDE 2

≈ 10 min

  1. Go to arduino.cc/en/software and download Arduino IDE 2.x for your system (Windows, macOS or Linux).

  2. Run the installer and accept the defaults. If Windows asks to install USB drivers, click Install.

  3. Open Arduino IDE. You should see an empty sketch with setup() and loop().

Tip

Already have an old Arduino IDE 1.x? The kit manual recommends uninstalling it and installing the latest version.

STEP B

Add ESP32 boards

≈ 10 min

  1. Click the Boards Manager icon on the left side (or Tools › Board › Boards Manager…).

  2. Type esp32 in the search box. Find esp32 by Espressif Systems.

  3. Pick version 3.1.0 (the version the kit was tested with; newer 3.x versions also work with this site's code) and click INSTALL. It downloads a lot, so give it a few minutes.

  4. Wait for "Successfully installed platform esp32" in the Output panel.

esp32 doesn't show up in the search?

Open File › Preferences, paste this URL into Additional boards manager URLs, click OK, then search again.

STEP C

Install the CH340 USB driver

≈ 5 min

The USB adapter under the ESP32-CAM uses a CH340 chip to turn USB into serial. Windows needs a driver for it, otherwise no COM port appears.

  1. Download CH341SER from the chip maker's site: wch-ic.com › CH341SER (Windows). Mac and Linux usually work without a driver.

  2. Plug the ESP32-CAM adapter into your PC with the USB cable, run the installer and click INSTALL. You should see "Driver install success!"

  3. Open Device Manager (search for it in the Start menu) › Ports (COM & LPT). You should see USB-SERIAL CH340 (COMx). Remember the number.

No port?
  • Try a different USB cable. Many cables only carry power, not data.
  • Try another USB socket or another computer.
  • Uninstall the driver, restart the PC, and install again.

LAB 3

Fade the flash LED with PWM

≈ 15 min

Goal: learn PWM, the same trick we'll use later to control motor speed.

PWM switches a pin on and off thousands of times per second. The duty (0–255) is how much of each cycle the pin is ON. 0 = always off, 128 = half the time, 255 = always on. The LED (or motor) only "feels" the average.

Eyes

The flash LED is extremely bright at full power. Keep MAX_BRIGHTNESS low and don't look straight into it.

Try this

Make the LED "breathe" faster or slower by changing delay(20).

Module 3

Motors & wiring

The ESP32 can't power a motor directly: its pins give a few milliamps at 3.3 V, and a motor wants hundreds of milliamps. The L298N driver sits in between, like a set of electronic switches.

BUILD

Wire the robot

≈ 30 min

Goal: connect the battery, the L298N, the four motors and the ESP32-CAM exactly like the kit diagram. Batteries OUT while you wire.

Quick test

The kit comes with its firmware already loaded. Insert the batteries, lift the robot, switch on and press RST: the motors briefly run. That tells you the motor wiring is alive.

How the L298N makes a motor turn

Each motor channel has two inputs. Make one input "on" and the other "off" and the motor spins one way; swap them and it spins the other way; both off and it stops. In this kit the ENA/ENB jumpers stay on (channels always enabled), and the code sends PWM to the IN pins to set the speed. So a "1" in the table below really means "PWM at the current speed".

LAB 6

Motor test

≈ 15 min

Goal: check that every motor turns the right way. This replaces the kit firmware; you can re-upload it later from Module 4.

  1. Put the robot on a box or cup so the wheels hang in the air.

  2. Upload the sketch. Switch the battery on. After 2 seconds it runs forward, backward, left, right, once.

  3. Watch each wheel. Press RST to repeat.

What you seeFix
One wheel turns backwards on "Forward"Swap that motor's two wires in its OUT terminal.
A whole side turns backwardsSwap the two wires of that side's OUT terminal (or swap IN1↔IN2 / IN3↔IN4).
"Left" turns rightSwap the pin numbers of LEFT_* and RIGHT_* in the code.
Motors only buzzRaise speed (try 200) or charge the batteries.
Nothing movesBattery switch on? Shared GND wire connected? Batteries above 11.1 V?
Read the code

setMotors(l0, l1, r0, r1) writes one PWM value to each of the four L298N inputs. Every movement is just a different pattern of those four numbers, exactly like the table above.

Module 4

Control from your phone or PC

Now we cut the cable. The robot runs a small web server, and any phone or laptop browser becomes the remote. First with the kit's own firmware (with live camera), then with code you write yourself.

PART A

Drive with the kit firmware

≈ 15 min

Goal: use the factory program: camera stream plus drive buttons. If you uploaded Labs 1–7, re-upload the kit code first (Part B).

  1. Turn on the power switch. The small red LED on the ESP32-CAM lights up when its WiFi is ready. If not, press RST.

  2. On your phone open WiFi settings and join ESP32-CAM Robot (no password).

  3. Open a browser and go to 192.168.4.1.

  4. Hold a green button to drive; release to stop. Yellow buttons switch the flash LED.

Page won't load?
  • Turn mobile data off. Phones often send traffic over 4G/5G when the WiFi "has no internet".
  • Check you joined the right robot's WiFi.
  • Low batteries cause random resets. The total should be above 11.1 V.

Why the failsafe?

If your phone locks or walks out of range, the "stop" message may never arrive. The robot stops itself when it hears nothing for 0.6 s. Real robots always have a failsafe like this.

Module 5

MQTT: talk to robots through a broker

With a web remote, your phone talks straight to one robot. With MQTT, everything talks to a central broker, and the broker passes messages on. One dashboard can drive many robots, and many screens can watch one robot.

WordMeaningIn our robot
BrokerThe post office. Receives every message and forwards it.Mosquitto on the instructor's PC
TopicThe address on the envelope, like a folder pathimakewemake/robot/team01/cmd
PublishSend a message to a topicNode-RED publishes forward:800
SubscribeAsk the broker for every message on a topicThe robot subscribes to its /cmd topic
RetainedThe broker keeps the last message for newcomers/online stays "online" or "offline"
Last WillA message the broker sends if a client vanishesRobot loses power → broker publishes "offline"
Wildcards+ = one level, # = everything belowimakewemake/robot/+/online
Instructor: set up the classroom broker (Mosquitto on Windows) · once per class

  2. Open C:\Program Files\mosquitto\mosquitto.conf in Notepad (as Administrator), and add these lines at the end. Without them, Mosquitto 2 only accepts connections from the same PC.

  3. Allow port 1883 through the Windows firewall:

  4. If the Mosquitto Windows service is already running, stop it in Services, then start the broker so you can see every connection:

  6. Watch robots join:

Network

Robots, student laptops and the broker PC must be on the same 2.4 GHz-capable WiFi, and the network must allow devices to talk to each other. Guest networks with "client isolation" block this. A cheap dedicated router works best.

Module 6

Node-RED: flows and a robot dashboard

Node-RED lets you program by wiring boxes ("nodes") together in a browser. It speaks MQTT out of the box, and with Dashboard 2.0 it can build a control panel that works on any phone or PC.

SETUP

Install and start Node-RED

≈ 15 min

  1. Install Node.js LTS from nodejs.org (accept the defaults).

  2. Open Command Prompt (Windows) or Terminal (Mac/Linux) and run these one at a time. The first line should print a version like v22.x. On Mac/Linux you may need sudo before npm.

  3. Leave that window open. Open http://127.0.0.1:1880 in your browser: that's the Node-RED editor.

  4. Install the dashboard: menu ☰ › Manage palette › Install, search for this and click install:

Import a flow

For each lab below: click Copy, then in Node-RED open ☰ › Import, paste with Ctrl+V, click Import, then the red Deploy button (top right). Or use Download and choose select a file to import.

LAB 10

Drive with inject buttons

≈ 20 min

Goal: send commands with one click and watch the robot's status come back. Your team ID and broker IP are already filled in.

  1. Import and Deploy. Under each MQTT node a small green connected label should appear.

  2. Click the square button on the left of Forward 1 s. The robot drives for a second.

  3. Open the Debug sidebar (bug icon, top right) to see the status messages arriving every 2 seconds.

  4. Click Dance!. The Square dance function sends eight timed moves in a row.

LAB 11

Build a robot control dashboard

≈ 25 min

Goal: a real control panel with drive buttons, speed and step-time sliders, a light switch and live status, usable from any phone on the classroom WiFi.

  1. Make sure @flowfuse/node-red-dashboard is installed (Setup step 4), then import and Deploy.

  2. Open http://127.0.0.1:1880/dashboard.

  3. Each tap of an arrow moves the robot for the Step time set on the slider. STOP stops at once.

  4. On your phone (same WiFi), open http://<your-laptop-IP>:1880/dashboard. Find your laptop IP with ipconfig.

How it works

An arrow button sends forward → the add step time function turns it into forward:600 using the slider value it remembered in flow.stepMs → mqtt out publishes it. The robot's status JSON comes back through mqtt in → split status → four text widgets.

Challenges
  • Add a gauge widget that shows WiFi signal strength from msg.payload.rssi.
  • Add buttons for a second team's robot: copy the mqtt out node and change the topic.
  • Make the robot drive a square when its /online topic changes to "online".
  • Instructor challenge: one dashboard that sends the same dance to every robot in the room.

You made it

You've gone from blinking an LED to driving a robot through a broker from a dashboard. The same pattern (sensor or actuator → ESP32 → MQTT → Node-RED) runs smart greenhouses, factory monitors and home automation. Swap the motors for a sensor and you have an IoT device.
