Safety

18650 batteries store a lot of energy. Insert them the right way round (check + and −), never short the terminals, switch the robot off when you are not using it, and only charge them in a proper 18650 charger with someone watching.

Module 1

Set up your PC

You need three things before you can upload code: the Arduino IDE, the ESP32 board package, and the CH340 USB driver. Do this once per computer.

STEP A

Install Arduino IDE 2

≈ 10 min

  1. Go to arduino.cc/en/software and download Arduino IDE 2.x for your system (Windows, macOS or Linux).

  2. Run the installer and accept the defaults. If Windows asks to install USB drivers, click Install.

  3. Open Arduino IDE. You should see an empty sketch with setup() and loop().

Tip

Already have an old Arduino IDE 1.x? The kit manual recommends uninstalling it and installing the latest version.

STEP B

Add ESP32 boards

≈ 10 min

  1. Click the Boards Manager icon on the left side (or Tools › Board › Boards Manager…).

  2. Type esp32 in the search box. Find esp32 by Espressif Systems.

  3. Pick version 3.1.0 (the version the kit was tested with; newer 3.x versions also work with this site's code) and click INSTALL. It downloads a lot, so give it a few minutes.

  4. Wait for "Successfully installed platform esp32" in the Output panel.

esp32 doesn't show up in the search?

Open File › Preferences, paste this URL into Additional boards manager URLs, click OK, then search again.

STEP C

Install the CH340 USB driver

≈ 5 min

The USB adapter under the ESP32-CAM uses a CH340 chip to turn USB into serial. Windows needs a driver for it, otherwise no COM port appears.

  1. Download CH341SER from the chip maker's site: wch-ic.com › CH341SER (Windows). Mac and Linux usually work without a driver.

  2. Plug the ESP32-CAM adapter into your PC with the USB cable, run the installer and click INSTALL. You should see "Driver install success!"

  3. Open Device Manager (search for it in the Start menu) › Ports (COM & LPT). You should see USB-SERIAL CH340 (COMx). Remember the number.

No port?
  • Try a different USB cable. Many cables only carry power, not data.
  • Try another USB socket or another computer.
  • Uninstall the driver, restart the PC, and install again.

LAB 3

Fade the flash LED with PWM

≈ 15 min

Goal: learn PWM, the same trick we'll use later to control motor speed.

PWM switches a pin on and off thousands of times per second. The duty (0–255) is how much of each cycle the pin is ON. 0 = always off, 128 = half the time, 255 = always on. The LED (or motor) only "feels" the average.

Eyes

The flash LED is extremely bright at full power. Keep MAX_BRIGHTNESS low and don't look straight into it.

Try this

Make the LED "breathe" faster or slower by changing delay(20).

Module 3

Motors & wiring

The ESP32 can't power a motor directly: its pins give a few milliamps at 3.3 V, and a motor wants hundreds of milliamps. The L298N driver sits in between, like a set of electronic switches.

BUILD

Assemble the robot and motors

≈ 45 min

Goal: put the chassis, the four motors, the wheels, the camera holder, the L298N and the battery case together using the Thinklab assembly guide. Keep the batteries out until everything is wired.

Thinklab 4WD robot kit – assembly guide11 build steps, wiring diagram and finished photos (PDF, 3 pages, 3.5 MB)
Open PDF

  1. Steps 1–3 (page 1): screw the 4 aluminium blocks to the chassis (M3×10 mm), fix the 4 motors to the blocks (M3×30 mm screws + nuts), then push on the wheels and secure them (M2×25 mm self-tapping).

  2. Steps 4–7 (page 2): mount the camera holder, fit the camera ribbon into the ESP32-CAM, plug the ESP32-CAM onto its adapter, and fix the holder to the front of the chassis.

  3. Steps 8–11 (page 2): raise the L298N on the 4 copper spacers, stick the battery case on with Velcro, screw on the external antenna and connect it to the ESP32-CAM.

  4. Wiring (page 3): continue with Wire the robot below. It matches the "Wire it right!" diagram.

Quick test

The kit comes with its firmware already loaded. Insert the batteries, lift the robot, switch on and press RST: the motors briefly run. That tells you the motor wiring is alive.

How the L298N makes a motor turn

Each motor channel has two inputs. Make one input "on" and the other "off" and the motor spins one way; swap them and it spins the other way; both off and it stops. In this kit the ENA/ENB jumpers stay on (channels always enabled), and the code sends PWM to the IN pins to set the speed. So a "1" in the table below really means "PWM at the current speed".

LAB 6

Motor test

≈ 15 min

Goal: check that every motor turns the right way. This replaces the kit firmware; you can re-upload it later from Module 4.

  1. Put the robot on a box or cup so the wheels hang in the air.

  2. Upload the sketch. Switch the battery on. After 2 seconds it runs forward, backward, left, right, once.

  3. Watch each wheel. Press RST to repeat.

What you seeFix
One wheel turns backwards on "Forward"Swap that motor's two wires in its OUT terminal.
A whole side turns backwardsSwap the two wires of that side's OUT terminal (or swap IN1↔IN2 / IN3↔IN4).
"Left" turns rightSwap the pin numbers of LEFT_* and RIGHT_* in the code.
Motors only buzzRaise speed (try 200) or charge the batteries.
Nothing movesBattery switch on? Shared GND wire connected? Batteries above 11.1 V?
Read the code

setMotors(l0, l1, r0, r1) writes one PWM value to each of the four L298N inputs. Every movement is just a different pattern of those four numbers, exactly like the table above.

If your phone locks or walks out of range, the "stop" message may never arrive. The robot stops itself when it hears nothing for 0.6 s. Real robots always have a failsafe like this.

Module 5

MQTT: talk to robots through a broker

With a web remote, your phone talks straight to one robot. With MQTT, everything talks to a central broker, and the broker passes messages on. Our class broker lives on the internet at mqtt.imakewemake.online, so your robot, your laptop and your phone can reach it from any network that opens normal websites. Every student has a login and a private topic folder; the teacher can see everything.

WordMeaningIn our robot
BrokerThe post office. Receives every message and forwards it.mqtt.imakewemake.online, port 443, TLS
TopicThe address on the envelope, like a folder pathstudents/student01/cmd
Login + ACLUsername and password. The broker only lets you use your own folderstudents/student01/#
PublishSend a message to a topicNode-RED publishes forward:800
SubscribeAsk the broker for every message on a topicThe robot subscribes to its /cmd topic
RetainedThe broker keeps the last message for newcomers/status stays "online" or "offline"
Last WillA message the broker sends if a client vanishesRobot loses power → broker publishes "offline"
Wildcards+ = one level, # = everything belowstudents/+/status (teacher only)

Your connection settings

Topic rules

You can only publish and subscribe inside students/student01/. The broker does not show an error for other topics (like test, # or another student's folder): the message simply never arrives. Always double-check the topic.

Network

No broker to install. The robot only needs 2.4 GHz WiFi with internet access. Port 443 (the normal HTTPS port) is used, so school and company networks work. Always use the name mqtt.imakewemake.online, never an IP address, or the certificate check fails.

Instructor: the class broker and the teacher dashboard
  • The broker is already running at mqtt.imakewemake.online:443 (MQTT over TLS, Let's Encrypt certificate). Give each robot or team one studentNN login.
  • Your teacher login can subscribe to everything (#). Use MQTT Explorer with the teacher login, or import the teacher dashboard flow into your Node-RED (section 9 of the class MQTT broker guide) to see every student tile, graphs and a "first to send" ranking at /class-monitor.
  • Robots publish online/offline on students/<user>/status, so they show as ONLINE/OFFLINE badges on the teacher dashboard. Their /telemetry JSON (speed, rssi, uptime) becomes graphs automatically.
  • For a ranking round, type cmd (or hello) as the topic to count; otherwise the robots' automatic telemetry ranks first.

How it works

mqtt in receives text like "27.4" → the to number function turns it into the number 27.4 and ignores anything else → the same message goes to the gauge, the text and the chart. The chart keeps the last hour.

LAB 13

The robot application: a control dashboard

≈ 25 min

Goal: drive the Lab 9 MQTT robot from a real control panel with drive buttons, speed and step-time sliders, a light switch, a square dance and live status, from any phone, anywhere.

  1. Make sure the robot is running the Lab 9 sketch and shows online. Import this flow and Deploy.

  2. Open the Robot page:

    https://nodered.imakewemake.online/student01/dashboard/robot

  3. Each tap of an arrow moves the robot for the Step time set on the slider. STOP stops at once. Square dance sends eight timed moves.

  4. Open the same address on your phone, on any network (WiFi or mobile data). In the phone browser choose Add to Home Screen to open it like an app.

Already exist?

If Node-RED says some nodes already exist, click Replace. Those are the shared dashboard base and broker settings that every flow on this site uses.

How it works

An arrow button sends forward → the add step time function turns it into forward:600 using the slider value it remembered in flow.stepMs → mqtt out publishes it to /cmd. The robot's telemetry JSON comes back through mqtt in → split status → four text widgets.

Challenges
  • Open the Square dance function and design your own routine: a zig-zag, a figure eight, a "parking" move.
  • Add a gauge that shows WiFi signal strength from msg.payload.rssi.
  • Make the robot drive a square when its /status topic changes to "online".
  • Instructor challenge: with the teacher login, one dashboard that sends the same dance to students/student01/cmd … students/student30/cmd.

You made it

You've gone from blinking an LED to driving a robot through a broker from a dashboard. The same pattern (sensor or actuator → ESP32 → MQTT → Node-RED) runs smart greenhouses, factory monitors and home automation. Swap the motors for a sensor and you have an IoT device.
